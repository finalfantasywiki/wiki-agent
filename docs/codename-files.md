# Proposed `files` settings for Module:Codename/data

These are the proposed additions to the FF Wiki's release data. The bot reads them to build file names like `Cloud Strife from FFVII battle render.png`. They're grouped by the data page each entry lives on, so each page is **one edit**. These pages are used site-wide, and every save queues many pages for re-rendering.

The settings go in a `files` sub-table on a release or version, matching how the data already groups settings (`theme = { … }`, `terms = { … }`):

```lua
{ id = 'FFVIIR', ..., files = { shorthand = 'FFVII Remake', versionneutral = true } }
{ id = 'FFVI', ..., versions = { ['advance'] = { name = 'Advance', ..., files = { shorthand = 'GBA' } } } }
```

In the tables below, `shorthand = 'X'` means `files = { shorthand = 'X' }`, and `versionneutral = true` goes in the same `files` table.

Rules used:
- **Release `shorthand`:** only added when the codename isn't readable. Without it, the `id` is used (`FFVI`, `FFXIII`, `FFRK`…).
  - For a spin-off, the shorthand is its distinctive subtitle (`Crisis Core`, `Advent Children`).
  - For a remake or sequel of a numbered game, it's the numbered game's abbreviation plus the subtitle (`FFVII Remake`, `FFX-2`).
  - When the subtitle alone is too generic, it gets `FF ` in front (`FF Legend`, `FF Dimensions`).
- **Version `shorthand`:** only added when the version's `name` isn't the token itself. Without it, `name` is used. Platform shorthands: `PS`, `PS2`, `PSP`, `GBA`, `DS`, `NES`, `SNES`, `PC`, `mobile`.
- **`versionneutral = true`:** the release's images don't differ between versions, so its file names never carry a version.

Status: agreed 2026-11-01 and edited into the wiki on 2026-11-02, except IVTAY's release-level `files = { shorthand = 'The After Years' }`, which is still missing. The page texts were generated by a one-off script that isn't kept in the repo.

## New subpages: `/rel/FFIX`, `/rel/FFX`, `/rel/X2` and `/rel/VIICC`

`X2` follows FFX: versions for International and each HD Remaster platform, with the HD ones getting `files = { shorthand = 'HD' }`. `VIICC` keeps its fields but fixes two errors: its date was the North American one (now the original Japanese release, 2007-09-13), and its `psp` version had `title = '(PSP)'`, which `Module:Cite` would print as the game's title.


FFIX and FFX move from inline entries in `/rel` to their own subpages, filled out from their articles: release date, platform and credits; `versions` for every re-release; and the full `terms` set, linking to sections of `Final Fantasy IX stats` and `Final Fantasy X stats`. FFX's HD Remaster versions (`hd remaster`, `playstation 4`, `pc`, `nintendo switch`, `xbox one`) all get `files = { shorthand = 'HD' }`, so their files are named `… from FFX HD …`. FFIX has no `files` settings yet.

**Order matters:** create both subpages *before* saving `/rel`, which `require`s them. Otherwise every page that uses Codename shows a Lua error until they exist.

## Name fixes that make version defaults work

Without a `shorthand`, a version's token falls back to its `name`. The edits above give every messy name a `shorthand`, so these fixes aren't needed for the bot. They're still worth doing during the cleanup, after checking where the names are displayed, since templates may show them:
- FFIII, FFIV and FFV: version names in parentheses, e.g. `(NES)` → `NES`
- FFVIII: `playstation` has an empty name, and `remastered` is named `demo`
- IVTAY: `versions` is a list instead of keyed tables
- XIV1: `sub = 'false'` is a string, not a codename; remove the field instead (Module:Codename never matches it, so it already behaves as "no parent")
